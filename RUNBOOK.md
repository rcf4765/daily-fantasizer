# The Daily Fantasizer — weekly runbook

The weekly newspaper for the **Men Fantasizing** ESPN league (league 1196354715, season 2026, 12 teams, PPR, H2H points, lineup QB/2RB/2WR/TE/FLEX/D-ST/K, 14 regular-season weeks, 6 playoff teams). Owner/requester: Reza Jalali (team 1, Chimpanzini Bananini).

**The approved design is the graphics-first layout introduced with the week 5 edition on 2026-10-13** ("less text, more graphics", subtle Detroit Lions accents, no memes, no trade rumors). Every new edition must look exactly like it: same template, same sections, same chart types, same voice. Only the data and words change. The older text-heavy tabloid design (week 4 reference) is archived in `legacy/` and must not be used.

## Weekly procedure

1. **Set up the workspace.** Attach **rcf4765/daily-fantasizer** with `add_repo` (owner `rcf4765`, repo `daily-fantasizer`, access `push`) and clone it to `/home/claude/daily-fantasizer`; work there. Only if the repo can't be reached, restore the files from the project folder instead (`project_read` each into the same layout). **Self-test before anything else**: `sha256sum` the files listed in `MANIFEST.txt` and compare; then `python3 facts.py data/week5_raw.txt && python3 render.py 5` and confirm `daily-fantasizer-week5.html` matches its manifest hash. That proves the pipeline reproduces the approved edition byte for byte. (Note: render.py reads `data/trades.json` and `data/trade_block.json`, which change weekly; if only the week 5 render hash differs and those files changed since 2026-10-13, treat it as expected.) The workspace cannot reach ESPN directly.
2. **Pick the week.** The edition covers the most recent *completed* week. NFL weeks end after Monday Night Football; ESPN finalizes overnight. If the user doesn't say, use (current matchup period − 1) on a Tuesday-or-later run.
3. **Get the data.** The GitHub Actions workflow (`.github/workflows/fetch.yml`, ESPN_S2/ESPN_SWID repo secrets) runs `fetch_espn.py` then `fetch_trades.py` every Tuesday ~5:17am Eastern (retry Wednesday) and commits `data/weekN_raw.txt`, `data/trades.json`, `data/trade_block.json`, crest updates and `data/latest.json`. So: `git pull`, then check `data/latest.json` and that `data/weekN_raw.txt` exists.
   - If it's missing, trigger it: `gh api -X POST repos/rcf4765/daily-fantasizer/actions/workflows/fetch.yml/dispatches -f ref=main -f 'inputs[week]=N'`, poll `gh api "repos/rcf4765/daily-fantasizer/actions/runs?per_page=1"` until `completed`, then `git pull`. "not final" means ESPN hasn't finished the week: stop and report.
   - 401/403/HTML means the ESPN cookies in the repo secrets expired. Tell the user to replace `ESPN_S2` and `ESPN_SWID` at https://github.com/rcf4765/daily-fantasizer/settings/secrets/actions. Never ask for or handle cookie values yourself.
   - The trade step is `continue-on-error`; if it failed, the Trade Desk / On the Block sections are left out. Say so in the report.
   - **Fallback only if GitHub is unavailable**: Claude in Chrome with `extract.js` (see the script header). Trade data can't be fetched that way; the section will be omitted.
4. **Compute facts.** `python3 facts.py data/weekN_raw.txt`. Read `data/weekN_facts.md` in full.
5. **Write `data/weekN_copy.json`.** Same schema as `data/week5_copy.json` (read it first, every time). Rules below.
6. **Render.** `python3 render.py N` → `daily-fantasizer-weekN.html`. Leftover placeholders must be `[]`.
7. **Check.** One headless screenshot pass (Playwright): 1200px and 400px wide, full page; `document.documentElement.scrollWidth` must equal the viewport width. Look at the hero starter strips, the glance chart axis, boom/bust names, scatter (crests must not sit on the quadrant labels), heat map, trade cards if present. Check all four tabs open, including **Rule Changes** (it must be in every edition: tab button `#tab-props`, pane `#proposals`, the link card at the end of Player Stats; it loads the league office, or says "Voting opens soon" when `league.json` has no `proposals_api`). Fix overflowing copy and re-render once.
8. **Fact-check** every number in the copy against `weekN_facts.md` (or `weekN_raw.txt` / earlier weeks' facts for history claims).
9. **Publish to the league website.** `python3 publish_site.py N`. It copies the edition to `docs/weekN.html`, makes it the homepage `docs/index.html` and rebuilds `docs/archive.html`. GitHub Pages serves `docs/` (deployed by `.github/workflows/pages.yml` on every push that changes `docs/`; Pages source = GitHub Actions since 2026-10-19, after the built-in deploy runner jammed) at https://rcf4765.github.io/daily-fantasizer/ (archive at `archive.html`), so the league's link never changes; nothing is texted or emailed. `publish_site.py` also adds the home-screen app tags (between `<!--app-->` and `<!--/app-->`, right after `<title>`) to every page in `docs/`; the install link for the league is https://rcf4765.github.io/daily-fantasizer/install.html (added 2026-10-19; Apple doesn't allow a link to add the icon by itself, so the page walks iPhone users through Share → Add to Home Screen and gives Android a one-tap Install button). Also publish the edition with the Artifact tool as a private preview for the user: `file_path` = `daily-fantasizer-weekN.html`, `icon` = `newspaper`, description "Week N edition of The Daily Fantasizer for the Men Fantasizing ESPN league". The `<title>` stays "The Daily Fantasizer".
10. **Save.** Commit `data/weekN_copy.json`, `daily-fantasizer-weekN.html` and `docs/` and push to `main` (the push is what updates the website; Pages rebuilds in a minute or two). Mirror `weekN_raw.txt` and `weekN_copy.json` (and `league.json`/crest files if changed) to the project folder.
11. **Report** in a few sentences: week, lead story, anything odd (unfinished week, unverified transactions, crest updates, missing trade data, and how many teams On the Block covered). If the Rule Changes tab is live, say which proposals passed or failed since the last edition (read them with a GET to `proposals_api`; never vote or propose). Say the website is updated and give its link.

## Writing the copy (voice and rules)

**Less text, more graphics.** The charts carry the story; words are captions. Keep every field near the lengths in `week5_copy.json`.

- **Voice**: tabloid sports desk, dry and specific. The joke lives in the numbers. Roast lineup *decisions* and results, never anyone's looks, family, job or personal life. **No memes** (the user removed them).
- **Every number comes from the data.** No invented quotes, injuries or NFL news. A 0-projection starter is "projected for zero", nothing more.
- **Team tokens** in prose: `{T7}` full name with crest, `{S7}` short name with crest. Headlines and titles are plain text.
- **No duplicates on the page** (user, 2026-10-19). The biggest-news section under the stat tiles comes first and owns its games. Pick `hero`/`lead` from a game that is NOT in facts' "Upsets, heartbreakers & the blowout" list; if that game is in the list anyway, render.py leaves the score box out (it prints a NOTE) and the `lead` must tell a different story (season angle, records, a different game) without repeating the banner's numbers or lines. Sidebar boxes, Blotter and Missing Persons must not retell those games either; the Scoreboard recaps can still cover them briefly.
- `announcement` (optional, added 2026-10-19): when `league.json` `announcements` has an entry for the edition's week, write `{team, kicker: "Announcements", title (≤ 4 words, e.g. "Just Married"), text (≤ 40 words)}`. It renders as a quiet card right under the biggest-news section. **Warm, never a roast**, and only the details the user gave (no invented names, places or jokes about the event). A light tie-in to that team's week is fine if true and not repeated elsewhere on the page (week 6: CeeDeez Nuts snapping its losing streak). (The week 6 Tyler Adams wedding card was removed at the user's request on 2026-10-19; don't add it back.)
- `hero`: `winner`, `loser` (usually the week's lead game, but never one already in the biggest-news section), `big` (the headline number, usually the margin), `label` (≤ 6 words). The starter strips under it are automatic.
- `lead`: kicker, headline (≤ 6 words), deck (one sentence, ≤ 20 words), **two** paragraphs of ≤ 35 words.
- `sidebar`: exactly two boxes. Box 1 `style: "hi"` "Strange but true"; box 2 `style: "plain"` analytical angle. Each has a `viz` (`bars` with rows `{team|label, value, alt?}`, or `wins` with `teams`) and ≤ 25 words of text.
- `recaps`: one per game keyed `"winnerId-loserId"`; headline ≤ 6 words, text ≤ 20 words (top performers, the bench verdict). The page-one game's headline is "See Page One".
- `honor`: Manager of the Week = fewest points left on the bench (ties: higher score). `big` with 2 decimals, `big_label` "pts left on bench", text ≤ 30 words.
- `blotter`: 4 teams, title = the charge (≤ 6 words), text ≤ 15 words. Booking number is automatic.
- `missing`: 4 starters with the biggest misses vs projection, names exactly as in facts; text ≤ 8 words.
- `pecking_notes`: all 12 teams, ≤ 6 words each.
- `forecast_blurbs`: one per next-week matchup keyed `"homeId-awayId"`, ≤ 8 words.
- `upsets` (**the week's biggest news**, right below the blue stat tiles, user 2026-10-19): one entry per game in facts' "Upsets & heartbreakers" list, keyed `"winnerId-loserId"`: `headline` ≤ 6 words, `text` ≤ 30 words. **This is the one place to be brutal**: rub salt in the loser's wound (the bench points, the benched player who'd have won it, the record they fell from, the losing streak) and hype the winner like they just won a title. Still roast results and lineup decisions, never people. The first game's headline is the page-one banner (giant type), so make it the best line in the paper. Records, ranks, margin and the red chips are automatic. The blowout is always there, so there is always at least one entry (`data/week5_copy.json` has the example). Another example: `"upsets": {"9-8": {"headline": "Undefeated? Not Anymore", "text": "{S9} walked into the No. 1 team's house at 1–2 and left with the belt. {S8} benched 28 points of Kyle Monangai and lost by 4.16."}}`.
- Automatic sections (no copy): stat tiles, hero strips, Week at a Glance, Scoreboard lanes, Points by Position, Position Kings, Season Heat Map, Good or Lucky?, Floor & Ceiling, Bench Hall of Shame, Power Rankings Over Time, Playoff Odds, Waiver Wire MVP, The Wire (verified transactions), Trade Desk, On the Block, forecast bars.
- **Running lore**: add rivalries/jokes/nicknames the user shares to `league.json` `lore` and weave them in later.
- **Announcements**: life events the user shares (weddings, babies, milestones) go in `league.json` `announcements` with the week they should run; the `announcement` copy field turns them into a card.

## Upsets & heartbreakers (added 2026-10-19 at the user's request; shown untitled under the stat tiles as the week's biggest news)

Computed in `facts.py` (`upsets` in the facts JSON, "Upsets & heartbreakers" in the facts digest), drawn by `render.py`. Records and ranks are **as of kickoff** (standings = wins, then points for, through week N−1).
- **Upset**: the winner had fewer wins going in **and** the loser was a top-`upset_top_n` (4) team going in or had at least `upset_win_gap` (2) more wins. Week 1 never has upsets.
- **Heartbreaker**: margin under `heartbreaker_margin` (2) points.
- **Blowout** (added 2026-10-19): the week's biggest-margin game is always included, so the section appears every week. Its chip adds "Perfect lineup still loses by X" when even the loser's best lineup falls short. A game can carry several stamps.
- Order (first = the full-width banner): upset + heartbreaker, then upsets by win gap, then heartbreakers by margin, then the blowout. In a quiet week the blowout is the banner.
- Fact chips for the loser (no label): points left on the bench; "Best lineup would have won" when true; their best benched player who belonged in the best lineup; a losing streak of 2+.
- The thresholds live in `league.json`; change them only if the user asks.

## Season sections (added 2026-10-18/19 at the user's request)

All automatic in `render.py`, no copy needed, and all need every `data/weekK_raw.txt` for weeks 1–N (otherwise they're left out; backfill as described under "Backfilling weekly raw files").
- **Power Rankings** (`teams.race`, replaced the line chart 2026-10-20 at the user's request): each team's crest slides up or down the all-play power ranking week by week (all-play wins, then points for, same rule as the Pecking Order), with the real record under each name so it isn't mistaken for the standings. Plays once when scrolled into view (1.5 s per week), Play button replays, week buttons jump; reduced-motion readers see the final order. On phones it's the first section of League & Teams (the Pecking Order is hidden there).
- **Playoff Odds**: needs `data/schedule.json`. Simulates the remaining regular-season weeks 10,000 times with a fixed seed (20260000 + N, so renders are reproducible). Each team's weekly score ~ Normal(mean, σ): mean = (season points + 3 × league average) / (weeks + 3); σ = league-wide standard deviation of each team's weekly scores around its own average. Standings by wins, then points for; top `playoff_teams` (6) make it. The note under the chart prints the league average and σ.
- **Floor & Ceiling**: min / median / max of each team's weekly scores, plus this week's score.
- **Bench Hall of Shame**: season sum of (best lineup − actual), stacked by week; ✕ marks each loss where the team's best lineup beat the opponent's actual score.
- **Waiver Wire MVP**: every free-agent/waiver ADD in the weekly TX rows; a pickup's points count only in weeks the adding team started him, from the add week on. Top 8 shown. A player re-claimed after being dropped counts as a pickup (e.g. Mahomes to Bedazzled Balls, week 1).

## Roster Radar (added 2026-10-19 at the user's request)

Automatic (no copy), built by `strength.py` from `data/players/*.json` (current rosters, PPR/g through week N, FantasyPros ROS consensus) and the weekly raw files (kickers and D/STs). One radar per team with nine spokes, one per lineup slot: QB, RB1, RB2, WR1, WR2, TE, FLEX, D/ST, K. A switch flips between **Weeks 1–N** and **Rest of season** (user: based on the whole season, not the current week).
- Player value. Weeks 1–N: PPR points per game played (same numbers as Player Stats). Rest of season: ROS consensus position rank turned into points with this season's scoring curve (rank k at a position = the k-th best PPR/g at that position, 3+ games); players the consensus doesn't rank get half PPR/g + half volume-expected PPR/g, capped below the last ranked player, injured reserve at a quarter. K and D/ST: weeks 1–N view = season points per game from the raw files with two games of league-average prior; rest-of-season view = ESPN's weekly projections for the coming weeks (`data/players/espn_kdst.json`), falling back to the season number. Owners for K/D/ST come from that file too (current rosters).
- Lineup: the best player fills QB, RB1, RB2, WR1, WR2, TE, then FLEX (best RB/WR/TE left), D/ST, K. Slot strength = 75% starter + 25% first backup at that position (user: depth counts, but less than quality).
- Scale: per slot, 50 = league average (dashed red ring), outer silver ring = the best team, centre = the worst. Cards are ordered by total strength across both views. Hover a dot or open "Lineup" for the players.
- Not touched by the midweek `players.yml` refresh; it updates with each edition.

## Sections added 2026-10-19 (user approved previews; all automatic, no copy)

`teams.py` and `desk.py` hold the exact rules in their docstrings. In short:
- **Matchup of the Week** (paper, after the forecast): the next week's game with the smallest spread. Both teams' rest-of-season Roster Radars overlaid (team A blue, team B ink) and all nine lineup slots projected for that week: QB–FLEX with the blended projection, D/ST and K with ESPN's projection (user, 2026-10-19: ESPN projects kickers and defenses; use it). Omitted when there is no next week.
- **Manager Report Card** (League & Teams): Lineups 40% (actual / best lineup each week), Waivers 25% (pickup points as starters, same rule as Waiver Wire MVP), Roster 35% (rest-of-season points per week of the current best lineup). Once a team has a completed trade it also gets Trades 15% (rest-of-season value received minus given) and its other weights become 35/20/30. Graded by rank: top fifth A … bottom fifth F.
- **One-Man Show** (League & Teams): share of starting-lineup points from each team's top scorer, plus the next two, with the even-share (1/9) line.
- **Trade Matchmaker** (League & Teams): one-for-one swaps between different positions, judged by each team's best rest-of-season starting lineup (pts/week). **Every team gets at least one idea** (user, 2026-10-19): win-win (both gain 0.3+, close consensus ranks) first, then small win-win (both gain, ranks up to 24 spots or 50% apart), then even swap (one team gains, the other gives up under a point a week). Teams with the fewest options pick first, preferring a real gain for that team, then the better tier, then an unused partner; then the best remaining win-wins fill up to 12 ideas (no team more than twice in that fill). Each player and pair of teams once. Gains shown signed, tier tag on each card. Suggestions only, never rumors.
- **Trend Lines** (Player Stats, after Player Lookup): pick a player (grouped by league team, then free agents; defaults to the owner team's top player). Actual PPR weeks 1–N vs. the blended projection made that week; posted projections for upcoming weeks; after that his rest-of-season points per game, zero on his bye; weeks 15–17 shaded as playoffs. Tiles: actual vs projected so far, weeks beaten, projected rest of season. Targets and snap % grid. Covers ~240 players (all rostered + ranked free agents).
- **Defense Matchups** (Player Stats, after Start/Sit): PPR per game each NFL defense allowed to QB/RB/WR/TE (players the fetch tracks), shaded vs league average, ranks, and week N+1 opponent or bye.
- **Steady or Streaky** (Player Stats, after Volume vs. Scoring): points per game vs. week-to-week swing (standard deviation), 3+ games and 6+ PPR/g, dashed medians, quadrant labels. Same hover/tap player card as Volume vs. Scoring (floor/median/ceiling, last 3, weekly bars). Controls (user, 2026-10-19): a **Team** dropdown (all teams, each league team, free agents) that spotlights and names that team's players, and RB/WR/TE/QB buttons that show or hide each position (QB starts hidden). ## Known quirks

- ESPN `record.overall` ignores in-progress games; facts.py computes records from the schedule.
- `TRADE_ACCEPT` rows carry no players; executed trades come from `TRADE_PROPOSAL` rows with status EXECUTED.
- Waiver adds not on the week's roster are marked UNVERIFIED by facts.py and flagged in the facts and never reported as moves.
- Playoff weeks: check `regweeks` in META and the schedule's matchup periods when week 15 arrives. If `next_week` is empty the forecast disappears automatically.
